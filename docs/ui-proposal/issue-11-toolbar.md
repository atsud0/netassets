# Issue 11 全站列表工具栏整改与验收

本轮统一列表筛选、保存视图、选择摘要与批量操作的布局，减少常驻流程说明。改动限定在前端展示层，不改变接口、筛选条件、选择范围、批量上限、保存视图数据或角色权限判断。

## 公共组件约定

- `web/src/components/ListToolbar.vue`：默认插槽放筛选或选择信息，`actions` 插槽放保存视图、辅助入口或批量按钮。左侧主区可伸缩，尾部操作区在空间足够时靠右，不足时按组换行。
- `selection` 不传表示普通工具栏；传入数量表示选择工具栏，零选择不渲染。选择数量使用 `role="status"`，批量按钮保留调用方原有权限条件和禁用校验。
- `actionsVisible` 仅控制辅助区显示，不卸载其内容，安全工单切换 Tab 时保留保存视图组件状态，也避免隐藏视图占据空行。
- `web/src/styles/list-toolbars.css` 统一控件最小高度 32px、组内间距 8px、分区间距 20px，窄屏断点 760px。控件不强制拉满，也不通过固定高度或隐藏溢出来掩盖布局问题。
- `list-action-group` 用于不可混淆的功能组；页头操作使用 `page-heading-actions`。不再新增页面私有的筛选/批量 flex 规则覆盖公共契约。
- `ContextHelp.vue` 使用原生 `details/summary`，默认收起，支持键盘展开；一般规则与流程按需展示。真实错误、权限限制、危险操作警告和逐项失败原因不放进折叠帮助。
- `SavedFilterViews.vue` 常驻视图选择和保存入口，将设默认、删除移到“视图管理”菜单；保留默认视图禁用、删除确认、错误反馈及原有事件。

使用方式：

```vue
<ListToolbar label="资源筛选">
  <el-input v-model="keyword" aria-label="搜索资源" />
  <template #actions><SavedFilterViews page-key="assets" :current-filters="currentFilters" @apply="applyFilters" /></template>
</ListToolbar>
<ListToolbar v-if="canManage" :selection="selectedRows.length" label="批量操作">
  <ContextHelp label="选择范围">仅作用于选中记录，单次最多 200 项。</ContextHelp>
  <template #actions><el-button @click="submitBatch">批量处理</el-button></template>
</ListToolbar>
```

## 回归方式

```sh
make test-frontend
make e2e

# 已构建独立 E2E 应用时，可在同一容器环境聚焦工具栏验收：
podman compose -p netassets-e2e -f compose.e2e.yaml run --rm playwright npx playwright test --config toolbar-layout.config.ts
```

测试与浏览器均在 Podman 容器中运行。`BASE_URL` 使用 Compose 的测试应用地址时，布局配置不再启动额外 Vite；也可以在独立 Node 容器启动 5174 预览并让浏览器容器连接。所有布局数据由测试内模拟 API 提供，不读取或修改正式环境业务数据。`CHROMIUM_PATH` 仅用于容器内已有浏览器路径覆盖。

### 验证边界

- 本次布局复核使用 Playwright 1.55.1 驱动本地容器的 Chrome for Testing 150.0.7871.24（显式 `CHROMIUM_PATH`），不据此宣称已经覆盖项目默认 Playwright 镜像捆绑的 Chromium 版本。
- 此布局套件使用模拟 API；真实集团/子公司/执行人员会话的权限与业务流程由独立的业务 E2E 套件验证。
- 没有覆盖 Firefox、WebKit、真实移动设备、200% 缩放或完整无障碍审计。
- 全站空数据冒烟不等于每个页面所有详情、弹窗、加载/异常和复杂权限组合都已人工逐一验收。重点验证安全工单详情与导入弹窗；其他业务弹窗仍需结合真实数据专项回归。
- 历史前图与本轮截图的数据、早期页面样式不同，不能据此推导精确的高度节省或业务性能变化。
