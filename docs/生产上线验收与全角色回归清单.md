# NetAssets 生产上线验收与全角色回归清单

> 适用范围：集团总部统一部署、子公司分级填报和集团安全运营场景。
> 历史清单基线：数据库迁移 `00050_security_test_requests.sql`，四个内置角色（文档编写时）。当前代码迁移已到 `00089`；上线验收须以部署版本实际迁移状态及当前角色矩阵为准。
> 原则：生产验收脚本只读；会创建测试组织和账号的全角色回归只能在隔离的验收环境执行。

> 用户反馈缺陷的逐项状态见[缺陷复现与修复回归台账](缺陷复现与修复回归台账.md)。本轮仍有待验证/待处理项，不能将单元测试通过视作全部缺陷关闭。
> 部署本轮质量整改修复须包含迁移 00088（指派事件约束）和 00089（豁免到期索引）；豁免到期由独立分钟级任务处理，备份期间会延后重试，不能依赖每日巡检代替。

## 2. 上线前配置冻结

### 2.1 发布物

- [ ] 记录 Git commit、版本号、构建时间和应用镜像摘要；部署主机使用同一摘要。
- [ ] 代码工作区无未提交改动；数据库迁移文件与应用镜像来自同一 commit。
- [ ] `.env`、Compose 文件和反向代理配置完成评审并冻结，禁止临时手工修改容器内部文件。
- [ ] 记录 PostgreSQL、Podman、操作系统版本及容量基线。

### 2.2 账号与密钥

- [ ] `APP_ENV=production`。
- [ ] `SESSION_COOKIE_SECURE=true`，外部访问全程 HTTPS。
- [ ] `POSTGRES_PASSWORD`、`BOOTSTRAP_ADMIN_PASSWORD` 使用不同的随机强密码，不使用示例值。
- [ ] 集团名称、简称和管理员显示名称已替换示例值。
- [ ] 首次登录后修改初始化管理员密码，并至少配置两名集团管理员，避免单点账号失效。
- [ ] 生产环境变量文件权限限制为部署账号可读，不进入 Git。
- [ ] 反向代理只透出 HTTPS；PostgreSQL 端口不对办公网或互联网暴露。

执行只读配置预检：

```bash
ENV_FILE=.env BASE_URL=https://assets.example.com \
  ./scripts/production-acceptance.sh --preflight
```

`sslmode=disable` 只可用于同一受控容器网络内的 PostgreSQL；跨主机数据库连接必须启用传输加密并校验证书。

## 3. 基础设施与运行状态

- [ ] PostgreSQL 数据目录使用持久化卷，应用 `/data` 使用独立持久化卷。
- [ ] 数据盘剩余空间满足至少 6 个月增长和两份完整备份；设置磁盘告警。
- [ ] 主机时间、时区和 NTP 正确；应用统一保存 UTC 时间并按用户区域展示。
- [ ] 复核 `DATA_QUALITY_AUTO_SCAN_ENABLED`、`DATA_QUALITY_AUTO_SCAN_TIME` 和 `DATA_QUALITY_AUTO_SCAN_TIMEZONE`；生产默认每日自动巡检时间避开备份、批量导入和数据库维护窗口。
- [ ] 容器配置 `restart: unless-stopped`，主机重启后应用能自动恢复。
- [ ] `/health/live` 返回 200，`/health/ready` 返回 200。
- [ ] `/api/v1/system/info` 返回 200，版本信息与发布记录一致。
- [ ] 数据库迁移与待发布代码一致（当前仓库最新迁移为 `00089`，须包含 `00088` 指派事件约束及 `00089` 豁免到期索引），不存在迁移失败或只升级应用未升级数据库的情况。
- [ ] 四个内置角色和集团安全运营三项权限映射完整；子公司管理员与填报员均持有 `security_test.request`。

执行运行中只读检查：

```bash
ENV_FILE=.env BASE_URL=https://assets.example.com \
  ./scripts/production-acceptance.sh --running
```

该命令不会登录、不会写入业务表，也不会创建备份；若报告没有备份，须先按变更流程创建备份并完成恢复验证。

## 5. 核心功能验收

### 5.1 身份与会话

- [ ] 登录、退出、首次登录强制改密正常。
- [ ] 用户可在“账户设置”修改本人显示名称、联系方式和密码。
- [ ] 角色、任职和数据范围只能由有权限的管理员修改。
- [ ] 禁用账号后不能新登录；重置密码后必须再次修改临时密码。
- [ ] 其他会话撤销、个人 API Token 创建/吊销和到期策略正常。

### 5.2 集团资产治理

- [ ] 集团基本信息、组织树、子公司和多组织任职正常。
- [ ] 业务系统和网络资产支持在线编辑、CSV/XLSX 导入、分页、筛选和保存视图。
- [ ] 网络资产可选“有效期至”贯通新增、编辑、列表、详情、模板、导入预检、正式导入、台账导出、字段级变更历史、填报快照和提交差异；留空表示长期有效。
- [ ] 业务系统和网络资产导入可先执行不落库预检，预检前后台账、导入历史和审计日志不增加；确认导入后结果与预检口径一致，期间新增重复数据时以正式导入结果为准。
- [ ] 同一系统可关联域名、URL、IP 等多条网络资产，而不是在单一“资产值”字段混填。
- [ ] 网络区域为集团可配置字典，可表达子公司、办事处、园区、VPC 等范围。
- [ ] 待确认资产审核、自定义字段、数据质量规则、扫描、整改和批量处理正常。
- [ ] “资产到期”规则仅允许网络资产 `expires_at`，提前提醒天数支持 0～3650；即将到期和已过期资产均可命中，延长/清空有效期或归档后再次巡检自动关闭问题，质量整改与消息中心可正常接续。
- [ ] 正式域名/URL 详情能分开展示人工有效期、RDAP 域名注册到期、TLS 证书到期、状态、来源、尝试/成功/下次刷新和失败原因；刷新不覆盖人工有效期，失败时保留最近成功值。
- [ ] 启用域名/TLS 到期质量规则后，手动巡检先受限刷新外部观测并展示处理、成功、失败、不支持和延后统计；私网、`http://` URL、泛域名和失败观测按设计降级且不阻断巡检。
- [ ] 填报任务创建、下发、提交、退回、重提、审核和快照留痕正常。
- [ ] 回收站恢复和冲突保护正常。

### 5.3 安全运营闭环

- [ ] 集团安全运营人员可创建安全测试批次、固化测试范围、上传/下载报告。
- [ ] 测试范围可分页搜索并逐项添加，也可按组织、业务系统、网络区域批量纳入未归档公网资产；重复资产自动跳过，超过 200 项时阻止纳入且不静默截断。
- [ ] 子公司可从本组织业务系统（已上报或待上报版本）和公网资产（含待上报工作版本）发起上线安全测试申请，范围 1～200 项并冻结快照；提交前执行与填报任务一致的必填项校验，error 级缺失阻止提交并逐条列出，warning 级放行。
- [ ] 上线安全测试申请流转完整：草稿→提交→撤回/驳回/取消→审批通过生成授权测试批次→批次完成且无未闭环发现后自动进入待上线审批→批准上线后待上报工作版本自动生成 `launch_release` 填报任务并提交集团审核，申请关闭并可追溯上报任务。
- [ ] 申请范围只允许本组织公网资产；内网资产在集团-子公司网络打通前不可选，接口已预留扩展。
- [ ] 集团侧通过/驳回/批准上线仅限集团安全角色；站点通知按申请提交、撤回、通过、驳回、达成上线条件、批准上线分别送达对应视角。
- [ ] 漏洞单条登记和批量导入正常，严重等级、责任组织、资产和系统关联正确。
- [ ] 漏洞风险接受、到期复核、撤销和审计留痕正常。
- [ ] 安全工单创建、下发、签收、处理中、提交复测、退回、关闭和取消正常。
- [ ] 子公司只能看到并处理本组织工单；草稿不向子公司泄露。
- [ ] 附件访问遵循工单可见性和操作权限。
- [ ] 消息中心只展示当前账号有权看到的通知，未读数、已读和跳转正常。

### 5.4 可用性与扩展性

- [ ] 列表接口返回 `{page, page_size, total, items}`，`total` 为真实总数。
- [ ] 20、50、100 条每页均可用，表格在内容区内部滚动，左侧导航固定。
- [ ] SPA 深层路由刷新正常，不返回 404。
- [ ] 100 条数据、较长文本和窄屏下安全测试页面与其他页面视觉一致。
- [ ] 业务系统、网络资产、待确认资产、测试申请、安全测试和安全工单页面顶部无独立统计卡；待确认资产筛选卡右侧显示“待处理”计数，安全工单在保存筛选视图下方显示符合筛选工单、处理中、待复测和逾期统计（逾期为红色），窄屏不溢出、不遮挡。
- [ ] 登录页在用户名处按回车只出现一条“请输入用户名和密码”提示且不发送登录请求；补齐密码后回车只发送一次登录请求、只出现一条“登录成功”消息。
- [ ] 文件上传大小、格式错误、重复数据和部分失败提示清晰。
- [ ] 网络资产、业务系统和填报任务 CSV 大台账均为流式响应，普通 API 的 30 秒 `WriteTimeout` 不会截断导出。
- [ ] 同步 XLSX 超过 5000 行时不在请求内全量构建，前端自动创建后台导出任务；用户也可主动创建后台任务。
- [ ] 后台 XLSX 按数据库分页并通过流式工作表写盘，进度、总行数、文件大小、完成时间和有效期展示正确。
- [ ] 后台导出只允许申请人查询、下载和删除；其他登录用户（包括其他管理员）查询和下载均返回不可见。
- [ ] 后台导出完成或失败后，仅申请人收到 `export_job` 站内消息，点击可定位到具体任务。
- [ ] 成功文件保留 7 天；到期后下载返回 410，任务标记过期且磁盘文件被清理。
- [ ] 应用在任务运行期间重启后，遗留任务可恢复排队并继续生成；同一用户同时最多创建 3 个排队或运行任务。

## 7. 人工组织隔离抽查

自动化通过后，至少使用两个真实验收子公司 A、B 进行人工交叉抽查：

- [ ] A 管理员无法在用户、资产、系统、质量问题和工单接口看到 B 数据。
- [ ] A 填报员不能新增用户、分配角色或访问安全测试批次。
- [ ] A/B 分别拥有同名资产时，集团去重和归属关系符合业务规则。
- [ ] 用户多组织任职后只能切换获授权组织，切换后列表范围同步变化。
- [ ] 自定义组织角色即使配置同名安全权限，也不能取得集团安全运营数据范围。
- [ ] 审计日志记录操作者、组织、资源、动作、请求 ID、来源 IP 和时间。

## 8. 安全与运维检查

- [ ] TLS 证书链、域名、有效期和自动续期正常；禁用不安全协议和弱密码套件。
- [ ] 配置反向代理请求体上限、超时、真实客户端 IP 和安全响应头。
- [ ] 登录失败、5xx、容器重启、数据库连接、磁盘、备份失败均有监控和告警。
- [ ] 日志不记录密码、Cookie、API Token 明文、数据库口令和附件内容。
- [ ] 防火墙只开放必要端口，Podman 管理接口和数据库不对普通用户开放。
- [ ] 对上传文件执行扩展名、内容类型、大小限制；生产侧补充恶意文件检测策略。
- [ ] 完成最小权限账号、主机补丁、依赖漏洞和镜像漏洞检查。

## 9. 上线后观察

### 15 分钟

- [ ] 容器无重启，live/ready 持续正常，无集中 5xx。
- [ ] 集团管理员和安全运营人员各完成一次登录与只读查询。
- [ ] 数据库连接数、CPU、内存、磁盘写入无异常突增。

### 1 小时

- [ ] 子公司管理员和填报员完成登录、列表分页和一条验收数据操作。
- [ ] 消息、审计和权限边界符合预期，无跨组织数据投诉。
- [ ] 日志中无迁移、SQL、附件存储和会话错误。

### 24 小时

- [ ] 每日自动数据质量巡检仅生成一个 `scheduled` 批次，执行人显示“系统调度器”，审计日志中的用户为空且触发类型为 `scheduled`；多实例部署未重复生成同日批次。
- [ ] 若故意制造一次巡检失败，服务端存在收敛后的失败审计且 15 分钟后能够重试，不会每分钟刷屏。
- [ ] 定时/人工备份完成且清单校验通过。
- [ ] 无持续性能退化、磁盘异常增长、会话大量失效或通知积压。
- [ ] 汇总遗留问题，确定修复版本、负责人和完成日期。
