# 集团级轻量网络资产管理系统建设方案

> 文档状态：方案基线稿
> 版本：V0.26
> 更新日期：2026-07-29
> 适用范围：集团及下属子公司网络资产统一填报、管理、审核、安全测试发现与整改协同

---

## 1. 文档说明

本文档用于明确集团级轻量网络资产管理系统的产品定位、组织与权限模型、核心业务流程、功能范围、数据结构、插件边界、技术架构及版本计划，可作为后续需求评审、原型设计、数据库设计和开发实施的基线。

本方案已确认以下基本前提：

1. 系统服务于集团及其下属子公司，不是单一公司或个人使用的资产台账。
2. 集团负责制定资产标准、下发填报任务、审核数据、登记安全发现、下发整改工单并查看全局统计。
3. 子公司负责登记业务系统、录入网络资产、持续维护台账并处理本组织安全工单。
4. 系统保持轻量，不建设完整 CMDB、通用 ITSM 或重型安全运营平台，仅提供与资产直接关联的安全整改闭环。
5. 自动发现、DNS 探测、HTTP 检测和自动扫描等能力不进入核心系统，后续以插件形式加入。
6. 系统优先支持集团内部私有化部署。

## 2. 产品定位

### 2.1 产品定义

本系统是一个面向集团和多级子公司的轻量网络资产管理、填报与安全整改协同平台。

集团通过系统统一管理组织机构、业务系统和网络资产，并向子公司下发周期性或专项资产填报任务；子公司在自身数据权限范围内登记业务系统、录入或导入网络资产、修正数据问题并提交集团审核，最终形成可查询、可追溯、可导出的集团网络资产台账。集团可进一步以审核后的互联网资产为授权测试范围，登记渗透测试或漏洞扫描发现，并向对应子公司下发安全整改工单，形成从资产识别到漏洞闭环的连续治理流程。

### 2.2 核心对象

系统围绕以下主要核心对象建设：

```text
集团/子公司（组织机构）
  └─ 业务系统
      └─ 网络资产
          ├─ 域名
          ├─ IP 地址
          ├─ URL/网站
          ├─ 网络服务
          └─ 其他网络资产

集团
  ├─ 资产填报任务
  │   └─ 子公司填报、提交、审核、退回和归档
  └─ 安全测试批次
      └─ 漏洞/安全发现
          └─ 安全整改工单
              └─ 子公司接收、整改、提交验证、退回和关闭
```

### 2.3 核心价值

- 统一集团网络资产的数据标准。
- 明确资产归属公司、关联系统和责任人。
- 支持子公司自主填报和日常维护。
- 支持集团集中审核、统计和导出。
- 识别集团范围内的重复、冲突和无归属资产。
- 保留完整的资产变更记录和用户操作日志。
- 将互联网资产与安全测试、漏洞发现和整改责任直接关联。
- 支持集团向子公司下发安全工单，并跟踪整改时限、复测结果和逾期情况。
- 通过插件扩展自动发现、扫描结果同步和外部通知等非核心能力；核心系统内置轻量站内消息中心。

### 2.4 建设原则

1. **轻量优先**：不建设与资产台账无关的复杂平台能力。
2. **集团统筹**：标准、任务、审核和全局统计由集团统一管理。
3. **属地维护**：子公司负责自身系统与资产数据的准确性。
4. **权限隔离**：子公司默认只能访问自身及授权范围内的数据。
5. **全程留痕**：新增、修改、删除、审核、导入和导出均可追溯。
6. **核心稳定**：不安装插件时，核心系统仍可独立完整运行。
7. **整改闭环**：安全发现必须关联资产、责任组织、整改工单和最终验证结果。
8. **插件扩展**：自动发现、自动扫描、通知和外部同步通过插件提供。
9. **数据可进可出**：重点保障 CSV/XLSX 导入、校验和导出体验。

## 3. 建设目标与非目标

### 3.1 第一阶段建设目标

第一阶段应实现以下完整业务闭环：

```text
集团创建子公司和账号
  ↓
集团下发资产填报任务
  ↓
子公司登记业务系统
  ↓
子公司在线录入或批量导入网络资产
  ↓
系统执行格式、完整性和重复校验
  ↓
子公司提交填报结果
  ↓
集团审核或退回
  ↓
审核通过并形成集团资产台账
  ↓
集团统一查询、统计和导出
```

安全工单闭环作为资产填报核心版之后的增强阶段建设。它复用已经审核的组织、业务系统、网络资产、负责人、权限和审计能力，不阻塞第一阶段资产台账上线。

### 3.2 第一阶段不建设的内容

- 在核心系统内直接执行自动化漏洞扫描、攻击利用或渗透测试。
- 大规模公网资产测绘。
- 服务器性能和网络流量监控。
- Agent 客户端。
- 复杂资产依赖拓扑。
- 面向行政、人事、采购和运维等场景的通用 ITSM 工单平台。
- 多级会签、会签转签、流程设计器等复杂 BPM 审批能力。
- 自动修复、自动攻击利用和自动安全处置。
- 完整云资源管理平台。
- 多租户 SaaS 商业化能力。
- 字段级动态权限体系。
- 任意第三方代码在线上传和执行。

## 4. 组织机构模型

### 4.1 组织层级

系统支持集团、子公司和部门的树形结构，例如：

```text
XX集团
├── A科技有限公司
│   ├── 信息技术部
│   └── 电商事业部
├── B金融服务有限公司
├── C信息技术有限公司
└── D海外业务有限公司
```

业务系统和网络资产的主要归属单位应为集团或子公司等公司级组织；部门用于记录维护或责任归属，不作为集团统计时的主要法人归属。

### 4.2 组织字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| 组织名称 | 是 | 集团、公司或部门完整名称 |
| 组织简称 | 否 | 列表和报表中的显示名称 |
| 组织编码 | 是 | 集团范围内唯一 |
| 组织类型 | 是 | 集团、子公司、部门、其他 |
| 上级组织 | 否 | 集团根节点无上级组织 |
| 组织负责人 | 否 | 组织管理负责人 |
| 联系人 | 否 | 资产填报联系人 |
| 联系方式 | 否 | 邮箱或电话 |
| 状态 | 是 | 启用、停用 |
| 备注 | 否 | 补充说明 |

### 4.3 组织管理规则

- 组织编码在集团范围内唯一，组织架构使用集团根节点下的真实树形结构展示，不再以分页平铺表格和“上级组织”列代替组织树。
- 集团根组织只允许维护基本信息，不能停用、迁移、调整为其他组织类型或删除。
- 集团管理员可以新增下级组织，并维护已有子公司、部门和其他组织的名称、简称、负责人、联系方式与备注。
- 非根组织可以在 `子公司 / 部门 / 其他` 之间调整类型，也可以迁移到新的已启用上级组织；迁移时当前节点及其完整子树整体移动，用户任职、资产和业务系统仍归属于原组织节点。
- 调整上级关系时禁止选择自身或自身后代，避免形成组织树循环。
- 停用组织前必须执行影响检查，至少统计用户任职、角色授权、网络资产、业务系统、下级组织、未完成填报任务、未关闭安全工单、未完成质量整改、网络区域和有效 API Token。
- 存在启用中的下级组织、未完成填报任务、未关闭安全工单或未完成质量整改时禁止停用；仅存在用户、资产或业务系统时允许停用，但必须由管理员进行显式二次确认。
- 停用组织后历史资产和业务数据继续保留，但该组织不得再作为当前工作组织、API Token 绑定组织或新增用户任职、资产、业务系统、网络区域、填报任务、漏洞、工单、质量扫描和资产候选的目标组织；相关会话的当前工作组织同时清空。
- 恢复启用前必须确认原上级组织仍存在且处于启用状态。
- 删除采用软删除并进入回收站，只允许处理已经停用且不存在下级组织、用户任职、角色授权、资产、业务系统、未完成事项、网络区域或有效 API Token 的空组织。
- 从回收站恢复组织时，原上级组织必须仍存在；恢复后的组织保持停用状态，由集团管理员再次显式启用，避免组织恢复后立即重新进入业务授权范围。
- 组织基本信息修改、层级迁移、类型调整、启用、停用、移入回收站和恢复都必须写入统一审计日志。

## 5. 用户、角色与数据权限

### 5.1 集团角色

#### 集团超级管理员

- 管理组织机构、用户、角色和系统设置。
- 查看和修改全集团业务系统及资产。
- 管理插件、备份和恢复。
- 查看全部审计日志。

#### 集团资产管理员

- 查看全集团业务系统和网络资产。
- 创建和管理资产填报任务。
- 审核、退回子公司提交的数据。
- 处理重复资产和归属冲突。
- 查看集团统计并导出集团台账。

#### 集团审核员

- 查看全集团填报数据。
- 审核或退回子公司提交内容。
- 查看数据变更和数据质量问题。
- 默认不能直接替子公司修改原始数据。

#### 集团查看者

- 查看全集团资产和统计数据。
- 根据授权导出数据。
- 不能新增、修改、删除或审核。

#### 集团安全运营员

- 查看全集团授权范围内的互联网资产和关联业务系统。
- 创建安全测试批次，登记或导入漏洞与其他安全发现。
- 向责任子公司下发安全整改工单，设置优先级和整改期限。
- 审核子公司的整改说明和证明材料，登记复测结果并关闭或退回工单。
- 默认不能管理组织、用户、系统配置和非安全类业务数据。

当前实现已提供内置集团角色 `security_operator`（集团安全运营管理员），默认授予 `security_test.manage`、`security_finding.manage` 和 `security_workorder.manage`。该角色可以读取集团安全运营表单所需的最小组织、资产和业务系统参考数据，但不能进入资产台账、业务系统、组织用户、系统设置、备份、回收站或审计管理。集团范围安全数据同时要求“内置集团角色 + 对应安全权限”，组织自定义角色即使配置同名权限也不能越权查看全集团安全数据。集团站内消息也按漏洞和工单权限分别授权，安全运营角色可以接收待复测、临期、逾期和风险复核通知，但不会因此获得集团数据质量通知。`group_admin` 保留全部权限，用于应急接管，但日常安全运营不再要求由集团管理员包办。集团管理员可为仅承担集团安全运营职责的账号只分配 `security_operator`，不配置任何子公司组织任职或组织角色，从账号创建阶段避免附带资产、用户等组织岗位权限。

### 5.2 子公司角色

#### 子公司管理员

- 在被授予 `user.manage` 权限的组织及其下级范围内，创建、编辑、启停用户并重置其密码。
- 为范围内用户配置组织任职、主组织、组织角色及数据范围；不得管理范围外任职、集团管理员或具有集团范围角色的用户。
- 不得创建、分配或修改集团范围角色；集团角色、集团管理员和跨范围多组织任职由集团管理员统一管理。
- 登记和维护本公司业务系统。
- 管理本公司网络资产。
- 执行批量导入和导出。
- 提交集团填报任务。
- 查看本公司操作记录和退回意见。

#### 子公司资产编辑者

- 新增、编辑本公司业务系统和网络资产。
- 使用 CSV/XLSX 批量导入。
- 处理集团退回的数据问题。
- 不能管理用户和组织机构。

#### 子公司查看者

- 查看和导出本公司数据。
- 不能新增、编辑、删除和提交审核。

#### 子公司安全整改负责人

- 查看集团下发给本组织的安全工单及授权展示的漏洞信息。
- 接收工单、填写整改计划、更新进度并上传整改证明。
- 提交集团复测，并根据退回意见继续整改。
- 不能查看其他子公司的工单、漏洞证据和测试范围。

第一版可由子公司管理员兼任整改负责人，后续再按需要配置独立人员或多人协同。

### 5.3 个人账户设置与管理员授权边界

- 所有已登录用户（包括集团管理员和子公司管理员）均可在“账户设置”中维护**自己的**显示名称、邮箱、手机号码、办公电话和登录密码；邮箱、手机号码和办公电话采用独立字段存储和展示。
- 用户修改密码时必须校验当前密码；成功后保留当前会话，并撤销同一账号的其他登录会话。
- 账户设置提供“登录设备”列表，展示当前有效会话的设备类型、浏览器、操作系统、IP、登录时间、最近活动时间和过期时间；用户只能查看自己的会话。
- 用户可退出指定的其他设备或一键退出全部其他设备；当前设备不可通过会话撤销接口误退出，应通过正常“退出登录”操作处理。每次设备撤销均写入审计日志。
- 管理员新建账号或重置密码时设置的是临时密码；新账号首次登录以及密码被重置后的首次登录，必须先设置正式密码。
- 强制改密期间，账号仅可访问当前身份、个人资料、修改密码和退出登录接口，不能进入资产、填报、工单、用户管理等业务功能；改密成功后解除限制。
- 用户本人不得在账户设置中修改用户名、账号状态、主组织、任职组织、组织角色、数据范围或集团角色。
- 组织任职、角色、数据范围、账号启停和管理员重置密码均属于授权管理动作，只能由另一位具备对应 `user.manage` 范围权限的管理员通过“用户管理”完成。
- 为避免授权覆盖或越权，子公司管理员不能编辑自身，也不能编辑任一存在范围外任职的用户；其自身资料和密码统一从“账户设置”维护。
- “账户设置”提供个人 API Token 管理入口，用户可为脚本或外部工具创建、分页查看和撤销自己的 Token；每名用户最多同时保留 10 个未过期有效 Token，有效期限制为 1～365 天。
- API Token 固定绑定创建时的当前工作组织，调用业务接口时实时继承用户当前有效的角色与数据范围；用户停用、绑定组织任职移除、组织停用、Token 到期或撤销后必须立即失效。
- Token 明文仅在创建成功后展示一次，数据库仅保存 SHA-256 摘要和用于识别的短前缀；管理员停用账号或重置密码时自动撤销该账号全部有效 Token。
- API Token 通过 `Authorization: Bearer nat_xxx` 调用普通业务接口。个人资料、修改密码、登录设备、当前组织切换、退出登录和 Token 管理等账户安全操作仅允许浏览器 Session，禁止 Token 自行创建或撤销 Token。
- Token 创建、撤销均写入统一审计日志；最后使用时间采用限频更新，最多每 5 分钟写库一次，避免脚本高频调用放大数据库写负载。

### 5.4 用户查询与详情

- 用户管理支持按用户名、显示名称、邮箱、手机号码和办公电话进行关键词搜索。
- 支持按账号状态、任职组织和角色筛选，并采用后端分页，防止大规模账号列表一次性加载。
- 用户详情统一展示账号状态、联系方式、是否待首次改密、集团角色以及多组织任职、主组织和各任职的数据范围。
- 搜索、筛选、分页和详情接口必须应用与编辑操作相同的组织管理边界，不能通过查询条件探测范围外用户。

### 5.5 数据范围

系统内置以下数据范围：

```text
全集团
本组织及下级组织
本组织
本人负责的数据
```

每个用户的最终权限由“功能权限”和“数据范围”共同决定。

### 5.6 多组织任职

一个用户可以被授权管理多个组织，例如：

```text
用户王某
├── A公司：查看者
├── B公司：资产管理员
└── C公司：审核员
```

用户可以切换当前组织视角，集团级角色可以直接查看全集团数据。

### 5.7 权限实现原则

- 所有数据权限必须由后端接口强制校验。
- 不能仅通过前端隐藏菜单实现权限隔离。
- 导入、导出、插件任务和候选资产同样必须进行组织权限校验。
- 子公司上传文件时，不能通过篡改文件内容向其他公司写入数据。
- 集团审核员默认只审核、不代替子公司直接修改原始数据。

```text
所属公司
```

```text
建设中
```

### 6.4 系统管理功能

- 新增、编辑、查看和软删除业务系统。

### 6.5 业务系统数据安全属性

业务系统除基本信息和网络资产外，还应支持扩展数据安全属性。这类属性归属于业务系统，不直接归属于域名、IP 等单条网络资产；网络资产可以通过所关联的业务系统继承相应的风险和关注属性。

建议在业务系统详情页增加“数据安全”页签，记录以下信息：

| 字段 | 类型 | 建议选项或说明 |
|---|---|---|
| 是否处理个人信息 | 枚举 | 是、否、未知 |
| 是否处理敏感个人信息 | 枚举 | 是、否、未知 |
| 个人信息类型 | 多选 | 身份信息、联系方式、金融账户、行踪轨迹、生物识别、医疗健康、未成年人信息、其他 |
| 是否包含未成年人信息 | 枚举 | 是、否、未知 |
| 涉及自然人数 | 数字 | 受数据处理活动影响或涉及的自然人数 |
| 个人信息记录量 | 数字 | 系统存储或处理的个人信息记录条数 |
| 数据量区间 | 枚举 | 1万以下、1万至10万、10万至100万、100万至1000万、1000万以上、未知 |
| 是否超过10万条 | 派生字段 | 由个人信息记录量或数据量区间自动计算，不允许手工维护 |
| 数据统计口径 | 文本 | 例如有效用户数、客户主表记录数、交易明细记录数 |
| 数据基准日期 | 日期 | 本次数据量统计对应的日期 |
| 是否为估算值 | 布尔 | 标记数据量是否为估算结果 |
| 是否涉及重要数据 | 枚举 | 是、否、待识别 |
| 是否涉及核心数据 | 枚举 | 是、否、待识别 |
| 数据敏感等级 | 枚举 | 按集团数据分类分级标准配置 |
| 是否包含商业秘密 | 枚举 | 是、否、未知 |
| 是否包含客户数据 | 枚举 | 是、否、未知 |
| 是否包含员工数据 | 枚举 | 是、否、未知 |
| 是否向第三方提供 | 枚举 | 是、否、未知 |
| 是否存在跨境传输 | 枚举 | 是、否、未知 |
| 数据存储位置 | 文本或选项 | 自建机房、云平台、境内区域、境外区域等 |
| 数据保留期限 | 文本或数字 | 按集团统一口径填写 |
| 分类分级状态 | 枚举 | 已完成、进行中、未开展 |
| 填报人 | 用户 | 本次数据安全信息的填报人员 |
| 确认人 | 用户 | 对数据安全信息进行确认的人员 |
| 最近确认时间 | 日期时间 | 最近一次确认日期 |
| 补充说明 | 多行文本 | 统计口径、特殊情况和佐证说明 |

“涉及自然人数”“个人信息记录量”和“数据存储容量”是不同指标，不应混用。系统应优先保存原始数值、统计口径和基准日期，再根据集团规则自动计算“是否超过10万条”等关注标识，避免阈值调整后要求所有子公司重新填报。

### 6.6 固定字段与集团自定义字段

数据安全字段采用“核心固定字段 + 集团自定义字段”的组合方式：

- 集团经常统计、筛选和用于规则判断的字段采用固定字段。
- 专项检查或阶段性需求使用集团自定义字段。
- 自定义字段由集团管理员统一创建、命名和维护选项。
- 子公司只能填写被授权字段，不能自行创建同义字段破坏集团统计口径。
- 集团可以设置字段适用的组织、业务系统类型、填报任务、是否必填及填写说明。

自定义字段类型按轻量优先分层支持：

```text
当前已实现：单行文本、多行文本、数字、日期、单选、多选、是/否
后续按需扩展：未知态枚举、用户、组织、附件
```

当前实现边界：集团管理员可按“网络资产”或“业务系统”创建、编辑、启停并排序字段；字段编码、对象类型和字段类型在创建后保持不可变，以避免存量值语义变化。拥有对象维护权限且处于授权组织范围内的用户可填写字段值，字段值更新与字段定义变更均写入审计日志。已停用字段不再出现在日常填写表单中，但保留历史值以保证数据可追溯。

自定义字段值已纳入每次填报提交的不可变明细快照：快照同时保存字段编码、当时的显示名称和值；提交差异按 `custom:<字段编码>` 比较并展示“自定义字段：字段名称”。因此，即使集团后续更名或停用字段，历史提交仍按提交当时的名称和值可读；多选字段比较不受填写顺序影响。

自定义字段同时纳入 CSV/XLSX 批量导入和台账导出：用户必须先选择导入目标组织，再下载该组织有维护权限的模板；模板在固定列后追加稳定机器列名 `custom:<字段编码>`，XLSX 额外提供“自定义字段说明”页展示字段名称、类型、必填状态和选项。导入按字段类型校验文本、数字、日期、单选、多选和布尔值，单行基础数据与自定义字段值在同一事务中保存；错误只影响当前行。台账导出追加当前启用字段列，多选以中文分号分隔、布尔值输出为“是/否”。字段后续停用时，模板和普通台账不再新增该列，但历史存量值及填报快照继续保留。

例如年度数据安全盘点可以临时要求填写：

- 是否完成个人信息保护影响评估。
- 数据库加密方式。
- 数据脱敏方式。
- 第三方共享协议编号。
- 数据销毁周期。

### 6.7 数据安全关注规则

集团可以基于业务系统和网络资产的组合条件定义数据质量或高关注规则，例如：

```text
互联网暴露 = 是
且
涉及敏感个人信息 = 是
且
个人信息记录量 > 100000
```

系统可以据此形成以下视图：

- 公网暴露且涉及敏感个人信息的系统。
- 公网暴露且个人信息记录量超过10万条的系统。
- 涉及个人信息但长期未确认的系统。
- 涉及重要数据但尚未完成分类分级的系统。
- 存在跨境传输的系统。
- 已下线但仍保存个人信息的系统。

该能力用于集团数据治理、筛选和关注标记，不替代正式的合规认定或风险评估。

当前已实现的轻量可配置质量规则包含三类：一是“字段必填”，集团管理员可为网络资产或业务系统选择内置字段或 `custom:<字段编码>` 自定义字段，配置规则名称、错误/警告严重程度、启停状态和排序；该类规则会叠加到填报任务原有的固定质量检查中，错误项阻止提交，警告项仅提示。二是“长期未更新”，集团可分别为网络资产和业务系统设置 1～3650 天的未维护阈值，主动巡检时对比资源最后更新时间并生成可整改、可复核的问题。三是“资产到期”，仅作用于网络资产 `expires_at`，可设置提前 0～3650 天提醒；巡检命中即将到期及已经过期的未归档资产并生成持久化问题，后续修改或清空有效期、延长有效期或归档资产后，再次巡检会自动关闭不再命中的问题。

三类规则均支持有限条件：每条规则最多配置 10 个条件，多个条件固定按“且（AND）”组合。条件字段和运算符由服务端白名单控制，条件值全部通过 PostgreSQL 参数传递；可按组织、网络区域、资产类型、网络范围、环境、重要程度、业务系统关联状态、业务系统状态、互联网暴露和个人信息/重要数据属性等内置字段限定范围，也可使用集团已定义的自定义字段。选择型自定义字段的条件值必须来自集团配置选项。相同目标字段可按不同条件分别配置规则，条件顺序和值顺序会在保存时规范化，避免重复规则。

主动巡检和填报提交前的可配置必填检查复用同一套条件解释与 SQL 构造逻辑，组织范围继续由服务端强制约束。系统不支持任意 SQL、脚本、嵌套逻辑、OR 组合或跨资源表达式；复杂规则引擎、跨字段计算和自动修复建议继续后置，避免将轻量台账演变为通用规则平台。

集团管理员还可对当前存量台账主动执行数据质量检测，并按组织、检查对象（网络资产/业务系统）和严重程度筛选范围。检测与填报提交复用同一套启用规则语义，返回扫描资产数、扫描业务系统数、启用规则数、错误数、警告数和问题总数，并形成可定位到具体资源、所属组织和缺失字段的问题清单。单次最多返回 500 条问题明细，但问题总数保持精确统计；超过上限时提示缩小筛选范围。检测只读不修改台账，每次执行均写入审计日志。

### 6.10 当前轻量实现

当前版本已完成业务系统基础管理闭环：

- 支持列表、新增、详情和在线编辑。
- 支持负责人、联系方式、运行状态、系统等级、互联网暴露和部署方式维护。
- 支持个人信息、敏感个人信息、个人信息记录数、是否超过 10 万条、重要数据和核心数据属性维护。
- 填写个人信息记录数后，系统自动计算“数据量是否超过 10 万条”。
- 详情页展示所属组织、数据安全属性以及当前关联的网络资产。
- 支持归档和恢复；归档只改变系统状态，不删除关联资产。
- 支持软删除；仍有关联资产时禁止删除，并引导用户先解除关联或改用归档。
- 集团管理员可在授权范围内调整所属组织；子公司用户只能维护自身授权组织的数据。
- 新增、编辑、归档、恢复和删除操作均写入审计日志。
- 列表支持单次选择 1～200 个业务系统批量归档或恢复；执行前二次确认，服务端逐项校验组织数据权限，完成后展示每项成功或失败原因。

为避免资产归属关系被意外破坏，已关联网络资产的业务系统不能直接迁移至其他组织。集团管理员可在回收站恢复已删除的业务系统；恢复后统一保持“已归档”状态，待确认业务与安全条件后再手工启用。

## 7. 网络资产管理

### 7.1 第一版支持的资产类型

- 域名。
- IP 地址，包括 IPv4 和 IPv6。
- URL/网站。
- 网络服务，例如 `192.168.1.10:443`。
- 其他网络资产。

### 7.2 网络资产字段

| 字段 | 必填 | 说明 |
|---|---:|---|
| 资产类型 | 是 | 域名、IP、URL、服务、其他 |
| 资产值 | 是 | 资产主要标识 |
| 标准化值 | 是 | 系统用于去重和搜索 |
| 资产名称 | 否 | 便于用户识别 |
| 主归属公司 | 是 | 资产的主要责任公司 |
| 关联业务系统 | 否 | 可以关联一个或多个系统 |
| 维护部门 | 否 | 实际维护部门 |
| 负责人 | 否 | 资产责任人 |
| 环境 | 是 | 生产、预发布、测试、开发、办公、其他 |
| 网络暴露范围 | 是 | 公网、内网、未知；固定安全属性，用于安全统计与检查 |
| 网络区域 | 否 | 集团按所属组织配置；用于办事处、园区、云 VPC、灾备中心等资产归属范围 |
| 资产状态 | 是 | 正常、待确认、停用、已归档 |
| 重要程度 | 是 | 一般、重要、核心 |
| 来源 | 是 | 手工、导入、API、插件 |
| 标签 | 否 | 多个标签 |
| 备注 | 否 | 补充说明 |
| 有效期至 | 否 | 资产生命周期到期时间；适用于域名、临时 URL、公网 IP 租约等，留空表示长期有效 |
| 首次发现时间 | 否 | 插件发现时使用 |
| 最后发现时间 | 否 | 插件发现时使用 |
| 创建人/时间 | 是 | 系统自动记录 |
| 更新人/时间 | 是 | 系统自动记录 |

> “网络暴露范围”与“网络区域”分开维护：前者回答资产是否暴露于公网，后者回答资产位于或归属于哪个办公地点、园区、云网络或网络分区。比如某子公司可配置“上海办事处”和“深圳办事处”，两处资产仍可分别标记为内网或公网。
>
> 网络区域由集团管理员按组织配置，可维护名称、标识/地址范围、启停状态、排序和说明。子公司用户不能自行新增配置，只能在资产填报、在线编辑和批量导入时选择自己所属组织下已启用的区域；停用区域保留历史关联，但不可再用于新增或修改关联。
>
> “有效期至”表示资产本身的生命周期截止时间，不等同于 `updated_at`（台账最后编辑时间），也不专门表示 SSL/TLS 证书到期。系统根据当前时间动态展示长期有效、有效、即将到期或已到期，不另存冗余状态。该字段已贯通新增/编辑、列表/详情、CSV/XLSX 模板、导入预检与正式导入、台账导出、字段级变更历史、填报不可变快照及提交差异。日期型导入 `YYYY-MM-DD` 按 UTC+8 当日 23:59:59 解释；无时区的 `YYYY-MM-DD HH:mm:ss` 同样按 UTC+8 解释，同时支持携带明确时区的 RFC3339。

### 7.3 未归属系统资产

资产必须存在主归属公司，但可以暂时不关联业务系统。

常见场景包括：

- 文件导入后尚未完成系统归属梳理。
- 只知道资产属于某公司，不知道具体业务用途。
- 自动发现插件发现了新资产。
- 历史资产暂时无人认领。

系统应提供“未归属系统资产”视图，并在集团和子公司仪表盘中重点统计。

### 7.4 资产状态与审核状态分离

业务运行状态和数据审核状态不得混为一谈。

资产运行状态：

```text
正常
停用
已归档
待确认
```

数据审核状态：

```text
草稿
待审核
已通过
已退回
```

例如，一个运行状态为“正常”的资产，可以因为季度填报尚未审核而处于“待审核”状态。

### 7.5 当前轻量批量操作

网络资产列表支持勾选后执行轻量批量维护：

- 单次处理 1～200 个网络资产。
- 批量设置启用、待确认、停用或已归档状态。
- 批量设置网络区域，或清除已有网络区域。
- 批量设置网络区域时，前端要求所选资产属于同一组织，服务端仍逐项校验网络区域与资产所属组织是否一致。
- 执行前显示二次确认，执行后展示总数、成功数、失败数及逐项失败原因。
- 每个成功项复用单条编辑逻辑，继续保留字段级前后值、统一审计日志和组织数据权限校验，不引入独立批处理任务或消息队列。

业务系统的批量归档/恢复采用相同的逐项处理模型。批量接口不采用整批事务，避免某一条无权限或数据失效导致其他合法数据全部回滚；调用方可以根据逐项结果修正失败项后重试。

## 8. 资产标准化、去重与归属冲突

### 8.1 标准化规则

#### 域名

- 去除首尾空格。
- 转换为小写。
- 去除末尾的点号。
- 国际化域名使用统一编码格式。

示例：

```text
API.Example.COM.
```

标准化为：

```text
api.example.com
```

#### IP 地址

- 校验 IPv4/IPv6 格式。
- IPv6 转换为统一表示形式。
- 去除多余空格。

#### URL

- 协议和主机转为小写。
- 去除默认端口。
- 统一根路径。
- 保留非默认端口、路径和查询参数。

#### 网络服务

统一标准化为：

```text
协议://主机:端口
```

例如：

```text
tcp://192.168.1.10:22
https://api.example.com:443
```

### 8.2 集团级唯一资产实体

同一个网络资产可能被多家子公司使用，但集团资产库不应简单生成多条重复实体。

推荐模型：

```text
资产实体
├── 主归属公司
├── 使用公司
├── 运维公司
├── 关联业务系统A
└── 关联业务系统B
```

资产实体在集团范围内按“资产类型 + 标准化值”进行重复检测。

### 8.3 重复录入处理

子公司录入已存在资产时，系统提示：

```text
该资产疑似已在集团资产库中存在。
```

子公司可以：

- 申请关联已有资产。
- 提交归属确认。
- 返回修改。
- 说明不是同一资产并提交集团审核。

集团管理员可以：

- 合并资产。
- 设置主归属公司。
- 将其他公司设置为使用或运维单位。
- 确认两条记录不是同一资产。
- 退回子公司补充说明。

### 8.4 隐私和权限处理

当重复资产属于其他子公司且当前用户没有查看权限时，只提示“集团内存在疑似重复资产”，不直接展示其他公司的敏感明细。

## 10. 资产填报任务

### 10.1 功能定位

集团通过填报任务组织季度盘点、年度盘点、安全专项检查或其他集中数据采集工作。

### 10.2 集团创建任务

任务配置包括：

- 任务名称。
- 任务说明。
- 参与子公司。
- 开始时间和截止时间。
- 需要填报的资产类型。
- 网络资产核查范围：全部、公网或内网。
- 必填字段。
- 数据质量规则。
- 是否需要集团审核。
- 是否允许截止后提交。

### 10.3 状态设计

集团任务状态：

```text
草稿
进行中
已截止
已完成
已归档
```

子公司提交状态：

```text
未开始
填报中
已提交
已退回
已通过
逾期未提交
```

### 10.4 子公司填报流程

```text
打开填报任务
  ↓
确认现有业务系统和资产
  ↓
新增、编辑或批量导入数据
  ↓
执行完整性和重复校验
  ↓
修正数据问题
  ↓
提交集团审核
```

### 10.5 提交前检查

- 是否存在缺少负责人的核心系统。
- 是否存在缺少负责人的重要资产。
- 是否存在格式错误。
- 是否存在尚未处理的重复资产。
- 是否存在未关联业务系统的公网资产。
- 任务要求的必填字段是否完整。
- 是否存在待处理的集团退回意见。

### 10.6 集团审核

集团审核人员可以：

- 整体通过。
- 整体退回。
- 针对某个业务系统提出问题。
- 针对某条资产提出问题。
- 填写退回原因。
- 查看子公司修改前后的差异。
- 对整改后的内容再次审核。

### 10.7 日常维护与集中填报分离

为保持系统轻量，子公司日常维护不要求每次修改都经过集团审批。

- 日常修改：直接生效，但完整记录变更历史。
- 集中填报：从任务上下文新增的网络资产先保存为任务草稿，不立即进入集团正式台账；提交后按任务审核策略发布。
- 关键字段修改：可以进入专项审核。

当前任务草稿的发布规则如下：

```text
任务中新建网络资产
  ↓
保存到任务草稿区（集团正式台账不可见）
  ↓
子公司提交任务
  ↓
需要审核：集团审核通过后发布到正式台账
无需审核：提交事务内自动发布到正式台账
```

日常维护入口不属于任务草稿流程，仍直接写入正式台账并记录完整变更历史。第一阶段仅隔离“填报任务中新建网络资产”；任务内修改或删除已有正式资产、业务系统草稿、草稿自定义字段和草稿批量导入作为后续增强项。

建议纳入关键字段审核的内容：

- 主归属公司变更。
- 业务系统归属公司变更。
- 核心系统下线。
- 资产永久删除。
- 公网资产改为内网资产。
- 核心等级降低。
- 资产唯一标识修改。

### 10.8 提交快照与差异

每个组织每次提交填报结果时生成一份不可变快照，用于保留当时的业务系统、数据安全属性、网络资产及系统资产关联关系。快照不等待审核通过才生成，因此集团退回后，子公司重新提交会形成新的提交版本，不覆盖原快照。

当前快照机制包括：

- 保存任务、组织、提交人、提交时间、提交说明、提交版本、业务系统数量和网络资产数量。
- 按业务系统和网络资产保存资源 ID、稳定唯一标识、展示名称及结构化字段值。
- 自动关联该组织最近一次历史提交作为比较基线；基线可以来自同一任务的上一个重提版本，也可以来自上一期填报任务。
- 首次提交没有历史基线时，当前全部业务系统和网络资产均显示为新增。
- 差异分为新增、修改、删除/归档；修改项按字段展示修改前和修改后值。
- 集团管理员和该组织数据范围内的授权用户都可以查看提交差异，不能跨组织读取快照。
- 提交审计详情记录快照 ID、提交版本、上一快照 ID 和资源数量，便于后续追溯。

快照只保留业务台账字段，不复制附件文件，也不替代业务系统与网络资产的日常字段级变更历史。历史存量任务在该能力上线前只有数量快照，不反向伪造明细快照，界面不显示差异入口。

### 10.9 当前轻量实现

当前版本已经落地任务闭环的第一层能力：

- 集团创建任务、保存草稿、立即下发或后续下发。
- 填报任务接入轻量站内消息闭环：集团管理员接收子公司已提交待审核消息；具备 `inventory.manage` 且组织数据范围匹配的子公司用户接收新任务、审核退回、3 天内截止和已逾期消息。消息点击后按任务 ID 和目标组织 ID 自动定位并展开，清除定位后恢复完整任务列表。
- 创建任务时可按目标组织、填报资源类型和网络资产核查范围预览当前台账影响：展示每家组织的业务系统数、网络资产数及汇总，并提示当前范围内暂无资源的组织；预览仅用于下发前确认，不生成快照，组织实际提交时仍按届时最新台账和任务范围重新计算。
- 子公司开始填报，并在业务系统、网络资产模块维护本组织数据。通过任务详情进入网络资产页面时启用任务草稿模式：任务中新建资产只写入 `inventory_asset_drafts`，提交前不出现在集团或子公司的正式资产台账中；子公司可继续编辑或删除草稿。
- 草稿参与任务数量统计、提交前质量检查和提交快照。需要审核的任务在集团通过后发布草稿，无需审核的任务在子公司提交事务内自动发布；集团退回后草稿恢复为可编辑状态，发布冲突会整体回滚，不产生半发布结果。
- 子公司提交前执行固定、轻量的数据质量检查：按任务范围检查业务系统和网络资产是否存在、负责人信息是否完整、数据安全属性是否仍为未知，以及公网资产是否关联业务系统。
- 集团可在“数据治理”中追加可配置的字段必填规则和长期未更新规则：字段必填目标可为内置字段或集团自定义字段，长期未更新可按网络资产或业务系统设置 1～3650 天阈值；每条规则可配置最多 10 个白名单条件并按 AND 生效，可按组织、网络区域、资产环境、重要程度、数据属性或自定义字段等限定适用范围；可配置必填规则同时用于主动巡检和子公司填报提交检查。
- 集团主动巡检会生成可追溯的巡检批次并持久化全部命中问题；页面可查看扫描对象数、启用规则数、错误/警告数量、自动关闭数量和最近巡检批次。
- 相同规则、资源和责任组织重复命中时复用同一问题并累计命中次数；重新巡检不再命中的活动问题自动关闭，已关闭问题再次命中或限期豁免到期后再次命中会自动重新打开。
- 系统提供独立“质量整改”入口：子公司管理员在 `data_quality.manage` 授权组织范围内选择本组织有效任职用户作为负责人、开始整改并提交集团复核；集团管理员查看全集团问题、复核通过或退回、执行豁免和重新打开。
- 每次开始整改、提交、通过、退回、豁免、重新打开和自动关闭均保留问题事件与审计日志，并通过站内消息提示待复核、新问题、退回整改和豁免即将到期。
- 质量检查中的错误项会阻止填报任务提交；未关联业务系统的公网资产等提醒项会展示但不阻止提交。
- 子公司提交时记录填报说明，并生成业务系统与网络资产的不可变明细快照及数量汇总；快照包含自定义字段值和当时的字段显示名称。
- 同一任务退回重提会递增提交版本；新快照自动关联本组织最近一次提交，并计算新增、修改、删除/归档及内置字段、自定义字段的前后值。
- 集团审核人员可以在组织填报进度中直接查看差异，子公司授权用户也可查看自身组织的提交差异。
- 需要审核的任务由集团整体通过或填写原因退回；子公司可整改后重新提交。
- 集团退回时可对当前提交快照中的具体业务系统或网络资产填写逐条审核意见；单次最多 100 条，意见与提交版本和快照资源绑定。
- 子公司可查看该任务全部历史提交版本的逐条意见，按意见维护真实台账后重新提交；系统不额外引入逐条意见状态机。
- 不要求审核的任务在提交后自动通过。
- 所有目标组织均通过后，集团任务自动进入“已完成”。
- 集团可以关闭进行中任务，并归档草稿、已关闭或已完成任务。
- 开始、提交、审核、退回和状态变更均记录审计日志。

为保持轻量，当前质量检查采用内置固定规则，不引入动态规则引擎；提交快照和逐条审核意见采用 PostgreSQL 结构化记录，差异在请求时计算，不引入独立版本服务、搜索中间件或复杂审批引擎。整体退回原因与逐条意见在同一事务中保存；逐条意见不单独设置“整改中/已关闭”状态，子公司通过维护真实台账并提交新版本完成整改。

### 10.10 集团与子公司工作台

当前工作台已按用户数据范围提供轻量汇总：

- 集团管理员查看已启用下级组织、业务系统、网络资产、公网资产、进行中任务、待审核组织和逾期组织。
- 子公司用户查看本组织及授权范围内的业务系统、网络资产、待填报任务、被退回任务和逾期任务。
- 展示最近一项进行中或已完成任务的目标数、提交数、通过数和完成率。
- 汇总未关联业务系统资产、公网资产，以及公网且涉及敏感个人信息的业务系统数量。

工作台只读取现有台账和任务状态，不额外引入统计中间件或复杂报表引擎。


### 10.11 安全测试、漏洞发现与整改工单闭环

#### 10.11.1 功能定位

安全工单不是与资产管理无关的附加模块，而是审核后互联网资产的后续治理流程：

```text
子公司完成资产填报
  ↓
集团审核并形成互联网资产范围
  ↓
集团确认测试授权、时间窗口和目标快照
  ↓
线下渗透测试、人工检查或外部扫描
  ↓
在线登记或批量导入漏洞/安全发现
  ↓
集团确认归属并下发安全整改工单
  ↓
子公司接收、整改并提交证明
  ↓
集团复测验证
  ├─ 未通过：退回继续整改
  └─ 已通过：关闭工单和漏洞
```

核心系统负责测试范围、结构化发现、责任分派、整改协同、复测结果和审计留痕；实际扫描或渗透测试仍由经过授权的人员、工具或后续插件执行，第一版不在核心系统中集成攻击利用能力。

#### 10.11.2 轻量边界

第一版只建设“安全整改工单”，不建设通用 ITSM：

- 工单类型限定为漏洞、弱口令/配置风险、互联网暴露问题、证书问题、数据安全问题和其他安全问题。
- 使用固定状态机，不提供可视化流程设计器。
- 使用集团下发、子公司整改、集团验证的两级闭环，不引入多级会签。
- 先支持在线录入和 CSV/XLSX 导入测试发现，扫描器自动同步后续通过插件或标准 API 加入。
- 通知先采用站内待办；邮件、企业微信、钉钉等作为后续通知插件。

#### 10.11.3 安全测试批次

集团对某次渗透测试或安全检查建立测试批次，至少记录：

- 批次名称和测试类型。
- 测试发起部门、测试人员或外部服务商。
- 测试目标组织。
- 关联填报任务或资产快照。
- 授权的资产、域名、URL、IP 和端口范围。
- 明确排除的目标。
- 授权人、授权时间、测试开始和结束时间。
- 测试状态和说明。
- 原始测试报告和授权参考材料附件。

测试范围必须保存快照。资产后续发生变更时，不应自动改变已经授权的历史测试范围，避免出现测试对象和授权依据无法追溯的问题。

当前轻量实现已落地：

- 仅具备 `security_test.manage` 的集团管理员或集团安全运营管理员可创建和维护测试批次，子公司不展示跨组织测试范围。
- 测试类型支持渗透测试、人工检查、扫描测试、复测和其他。
- 状态固定为“草稿 → 已授权 → 测试中 → 已完成”，草稿、已授权和测试中可取消。
- 单批次选择 1～200 项未删除、未归档且网络暴露范围为公网的资产，可同时包含域名、IP、URL、网络服务和其他资产类型。
- 创建和编辑草稿时既可通过远程搜索、服务端分页逐项添加公网资产，也可按组织、业务系统或网络区域批量纳入其全部关联公网资产；批量结果自动去重，超过 200 项时明确要求缩小范围，不静默截断。
- 批量圈选仅负责把条件解析为现有 `asset_ids`，不改变批次核心数据模型；服务端继续执行公网、未归档、集团安全运营权限和 1～200 项最终校验。
- 草稿阶段可修改批次信息和范围；授权后范围冻结，禁止继续编辑。
- 快照保存资产类型、资产值、资产名称、责任组织、关联业务系统、网络区域、环境和重要程度。即使原资产后续修改或删除，历史授权范围仍保留。
- 创建、编辑、授权、开始、完成和取消均写入批次事件时间线与集团统一审计日志。
- 已授权、测试中和已完成批次可由具备安全测试管理权限的集团安全运营人员上传“测试报告”或“参考材料”；草稿与已取消批次不允许上传，避免未授权或撤销测试的材料混入正式证据。
- 测试批次附件使用受控文件存储和随机服务端文件名，支持 PDF、图片、TXT、CSV、XLSX、DOCX、ZIP，单个不超过 20MB；下载、删除均需要具备 `security_test.manage` 的内置集团角色会话，上传和删除写入批次时间线及审计日志。
- 安全发现可关联具体测试批次；在线登记和 CSV/XLSX 批量导入的结果均可追溯至授权范围快照。

#### 10.11.4 漏洞与安全发现

每条发现建议包含：

| 字段 | 必填 | 说明 |
|---|---:|---|
| 发现编号 | 是 | 集团范围内唯一编号 |
| 测试批次 | 否 | 来源于哪次测试或检查 |
| 责任组织 | 是 | 根据资产主归属确定，可由集团确认调整 |
| 关联资产 | 是 | 关联具体 URL、IP、域名或网络服务 |
| 关联业务系统 | 否 | 从资产关系带出，可人工确认 |
| 漏洞名称 | 是 | 如 SQL 注入、弱口令、过期组件等 |
| 漏洞类型 | 是 | 漏洞、配置风险、暴露问题、证书问题、数据安全问题、其他 |
| 严重等级 | 是 | 严重、高、中、低、信息 |
| CVE/CWE/CVSS | 否 | 支持行业通用标识和评分 |
| 影响说明 | 是 | 描述可能造成的业务或数据影响 |
| 发现位置 | 是 | 具体 URL、IP、端口、参数或组件 |
| 复现说明 | 否 | 仅向授权人员展示的验证步骤 |
| 证据附件 | 否 | 截图、请求响应、报告片段等 |
| 整改建议 | 是 | 集团给出的修复方向 |
| 发现来源 | 是 | 人工、渗透测试、扫描导入、API、插件 |
| 首次发现时间 | 是 | 用于统计漏洞存续时间 |
| 当前状态 | 是 | 待确认、已确认、整改中、待复测、已关闭、风险接受、误报 |

系统应在同一资产上根据“漏洞类型 + 发现位置 + 关键指纹”提示疑似重复，但不应未经人工确认直接合并不同批次的发现。

当前轻量实现已落地：

- 具备 `security_finding.manage` 的集团管理员或集团安全运营管理员可在线登记和编辑安全发现，并可选择一个处于“已授权、测试中或已完成”状态的安全测试批次。
- 选择测试批次后，关联资产限制在该批次的授权范围快照内；保存时由服务端再次校验，防止绕过前端越权关联。
- 安全发现列表展示测试批次编号和名称，导入后继续编辑时保留批次关联。
- 提供 CSV 和 XLSX 标准模板，模板列为：资产类型、资产值、漏洞标题、严重等级、漏洞类型、漏洞描述、验证证据、整改建议、发现时间。
- 单次导入文件不超过 10MB、最多 5000 行；支持 UTF-8 BOM CSV、XLSX、中文或英文严重等级以及常见日期格式。
- 导入时必须选择一个测试批次。系统只在该批次授权范围内，按照资产类型及标准化资产值执行精确匹配，并自动带出当前资产、责任组织和业务系统，不允许文件自行指定责任组织。
- 精确且唯一匹配的行直接生成安全发现；无匹配或多匹配的行不再作为普通格式错误退回，而是保存到“待关联漏洞”暂存区。
- 系统可针对 IP 端口、CIDR、URL/域名主机、URL 路径差异和泛域名给出相似资产建议及可信度；相似匹配仅供人工判断，不自动生成安全发现。
- 集团管理员或集团安全运营管理员可在待关联区筛选、查看原始行、人工关联或忽略；人工关联选项严格限制为当前测试批次的授权资产，服务端再次校验批次边界，不能指认到集团其他资产。
- 人工关联后按正式安全发现规则再次检查引用有效性和重复项；成功生成发现时保留处理人、处理时间、备注、审计记录，并向责任组织生成发现通知。
- 同一测试批次、同一资产、同一漏洞标题视为重复，不覆盖已有记录；候选人工关联时发现重复则将候选标记为重复。
- 导入结果展示总数、成功数、待关联数、重复数、失败数及逐行格式错误，并保存最近 100 次导入历史；候选被关联、忽略或判重后同步扣减该导入记录的待处理数量。
- 每条成功发现写入安全发现创建审计，整次导入和候选处理另写汇总或处理审计；自动扫描和扫描器同步仍保留为插件或标准 API 能力。
- 安全发现提供详情抽屉，统一展示漏洞描述、验证证据、整改建议、关联资产/系统、测试批次和风险接受记录。
- 仅具备 `security_finding.manage` 的集团管理员或集团安全运营管理员可以接受风险、撤销风险接受和执行风险复核；子公司只能查看本组织已下发工单关联发现的风险状态、原因、有效期和复核结论。
- 风险接受必须填写原因和未来有效期，记录接受人、接受时间、接受前状态；到期后不自动删除记录，列表和详情明确标记“已到期，待复核”。
- 风险复核必须填写复核意见，并可延长至新的未来有效期；已到期记录只有设置新的未来有效期后才能完成复核。
- 撤销风险接受时恢复接受前状态；通用编辑接口不能直接进入或退出 `accepted_risk`，避免绕过专用权限、原因、期限和审计要求。
- 存在未关闭整改工单的安全发现不能直接接受风险，避免风险状态与进行中的整改流程相互冲突。
- 接受、复核和撤销分别写入 `security_finding.accept_risk`、`security_finding.review_risk` 和 `security_finding.revoke_risk` 审计日志。

#### 10.11.5 安全工单字段

一张工单可以关联同一责任组织下的一条或多条安全发现，主要字段包括：

- 工单编号和标题。
- 工单类型。
- 下发组织和责任子公司。
- 关联业务系统、网络资产和安全发现。
- 严重等级、处置优先级和整改期限。
- 子公司整改负责人和协同人员。
- 集团发起人和验证人。
- 问题说明、整改要求和风险提示。
- 接收时间、开始处理时间、提交验证时间、关闭时间。
- 整改方案、整改结果、证明材料和子公司备注。
- 复测结果、复测说明和退回原因。
- 当前状态、逾期状态和完整事件时间线。

同一工单不得关联多个互不可见的责任子公司。如果同一个漏洞影响多个子公司，应创建一个集团整改批次，并为每个子公司分别生成工单，防止跨组织泄露资产和漏洞信息。

#### 10.11.6 工单状态机

```text
草稿 draft
  ↓ 下发
待接收 issued
  ↓ 接收
处理中 in_progress
  ↓ 提交整改结果
待验证 pending_verification
  ├─ 复测未通过 → 已退回 returned → 处理中
  └─ 复测通过 → 已关闭 closed

任意未关闭状态
  └─ 集团撤销 → 已取消 cancelled
```

“逾期”不作为独立业务状态，而是根据整改期限和当前状态实时计算。风险接受需要集团授权，并记录接受人、接受原因、有效期和到期复审时间，不能由子公司单方面关闭。

#### 10.11.7 权限与数据隔离

- 集团安全运营员可以查看全集团测试范围、发现和工单，并执行确认、下发、退回、复测和关闭。
- 子公司只能查看下发给本组织的工单，以及该工单关联且允许展示的资产与漏洞信息。
- 子公司不能修改漏洞等级、原始证据、集团整改要求和复测结论。
- 工单转派只能在本组织授权用户范围内进行；跨组织转派必须由集团处理。
- 严重漏洞的复现步骤、请求响应和附件可以设置为受限字段，仅指定人员可查看。
- 查看和下载漏洞证据、导出工单、修改期限、风险接受和关闭工单都必须记录审计日志。

#### 10.11.8 整改期限与提醒

整改期限应由集团按严重等级配置默认值，创建工单时允许授权人员调整，不在代码中写死。例如可以配置严重、高、中、低等级分别对应不同天数。

系统至少提供：

- 即将到期提醒。
- 已逾期提醒。
- 严重/高危工单长期未接收提醒。
- 子公司提交验证后的集团待办。
- 复测退回后的子公司待办。
- 风险接受即将到期提醒。

当前轻量实现采用“动态待办消息 + 用户已读回执”模型：消息根据当前工单和风险接受状态实时计算，不引入定时任务、消息队列或业务事件复制表；只有用户已读状态持久化。工单状态处理完成、期限调整或风险接受撤销后，对应消息会自动消失或生成新的消息 key。

消息中心至少包含以下分类：

- 集团管理员：安全工单待复测、工单逾期、工单 3 天内到期、风险接受已到期和即将到期。
- 子公司用户：收到新安全工单、复测退回、工单逾期和工单 3 天内到期。
- 支持未读筛选、分类筛选、单条标记已读、全部标记已读以及跳转到工单或安全发现详情。
- 消息查询严格复用组织数据权限；集团管理员可查看集团范围，子公司只能查看本组织责任工单。

#### 10.11.9 统计指标

集团工作台增加：

- 各子公司未关闭、待验证和逾期工单数量。
- 严重、高危漏洞数量和存续时间。
- 按组织、业务系统、资产、漏洞类型和来源统计。
- 整改完成率、按期完成率、平均整改时长和复测退回次数。
- 互联网资产覆盖测试比例。
- 重复出现或关闭后再次发现的问题。

子公司工作台增加“我的安全工单”“即将到期”“已逾期”“待补充材料”和“复测未通过”等待办指标。

#### 10.11.10 附件和敏感信息保护

- 测试报告、漏洞证据和整改证明使用受控附件存储，不直接公开文件路径。
- 附件下载必须经过会话、角色和组织权限校验，并写入审计日志。
- 原始口令、令牌、Cookie、个人信息样例等不应直接写入普通备注字段；确需保存时必须脱敏并限制访问。
- 限制文件类型和大小，并为后续病毒扫描或内容检查预留接口。
- 导出漏洞和工单时遵循当前用户的数据范围，并对敏感证据默认不导出。

#### 10.11.11 轻量站内消息中心

消息中心是填报、数据治理和安全工单闭环的轻量协同入口，不替代完整的通知平台。第一版不引入调度器、消息队列或独立消息服务，而是基于当前业务状态与持久化台账事件动态生成消息，并仅保存用户级已读回执。

消息记录至少包含消息 key、分类、标题、正文、等级、资源类型、资源 ID、处理路径、发生时间、截止时间和已读状态。消息 key 必须包含资源 ID 及状态时间或期限，避免同一工单再次退回、期限调整后错误复用旧已读状态。

集团和子公司的消息范围如下：

| 用户范围 | 消息 | 处理入口 |
|---|---|---|
| 集团管理员 | 填报提交待审核、待集团复测、逾期、3 天内到期、风险接受复核、质量复核和台账变更 | 填报任务、工单详情、安全发现详情、质量整改和对应台账 |
| 子公司用户 | 新填报任务、填报退回、填报临期/逾期、新工单、复测退回、工单临期/逾期、质量整改和台账变更 | 填报任务、工单详情、质量整改和对应台账 |

站内消息支持未读数量角标、未读/分类筛选、单条已读、全部已读和点击后跳转处理页面。邮件、企业微信、钉钉等外部通知保留为后续插件，不作为核心系统的运行前提。

## 11. CSV/XLSX 导入

### 11.1 支持格式

- CSV。
- XLSX。

### 11.2 导入对象

- 业务系统。
- 网络资产。

建议分别提供标准模板，避免一张表混合过多对象。

### 11.3 导入流程

```text
上传文件
  ↓
选择工作表
  ↓
识别表头
  ↓
映射系统字段
  ↓
数据预览
  ↓
格式、完整性和重复校验
  ↓
选择重复处理策略
  ↓
确认导入
  ↓
后台执行
  ↓
生成成功和失败报告
```

### 11.4 重复处理策略

- 跳过重复数据。
- 申请关联已有资产。
- 更新已有关系信息。
- 仅填充原记录中的空字段。
- 交由集团处理归属冲突。

默认策略为跳过或进入待处理队列，不允许子公司直接覆盖其他公司的资产信息。

### 11.5 业务系统模板字段

当前轻量版本由导入表单统一选择所属组织，不在每一行重复填写“所属公司”，避免子公司通过文件内容越权变更归属。标准模板字段为：

```text
系统编码
系统名称
系统简称
运行状态
系统等级
负责人
联系方式
互联网暴露情况
部署方式
系统说明
是否包含个人信息
是否包含敏感个人信息
个人信息记录数
数据量是否超过10万条
是否包含重要数据
是否包含核心数据
数据存储位置
数据安全备注
```

其中系统编码和系统名称必填；个人信息记录数存在时，系统自动计算“数据量是否超过 10 万条”。系统编码在集团范围内重复时跳过，不覆盖已有记录。

### 11.6 网络资产模板字段

当前轻量版本同样由导入表单统一选择所属组织，标准模板字段为：

```text
资产类型
资产值
资产名称
业务系统编码
环境
网络暴露范围
网络区域
重要程度
负责人
备注
```

资产类型和资产值必填；业务系统编码在所选组织范围内匹配。网络区域按导入表单所选所属组织的已配置名称匹配，未配置、已停用或不属于该组织时返回逐行错误。资产类型与标准化后的资产值在集团范围内重复时跳过，不覆盖已有资产。

业务系统和网络资产导入均提供正式写入前的“不落库预检”：预检复用正式导入的文件格式、表头、行数、自定义字段、业务系统/网络区域引用、字段格式和重复数据校验，返回可导入、重复、失败数量及逐行原因，但不创建台账数据、导入历史或审计记录。用户确认至少存在一条可导入数据后才能执行正式导入；预检与正式导入之间如台账发生变化，最终结果仍以正式导入时的数据库约束和逐行处理结果为准。

### 11.7 导入权限控制

- 子公司用户导入时，所属公司自动锁定为当前授权公司。
- 即使 Excel 中填写其他公司，也不能越权写入。
- 集团管理员可以导入多个公司的数据。
- 导入任务必须记录组织、操作人、文件名、时间和处理结果。

### 11.8 导入结果

导入完成后显示：

```text
总数据：1000
成功导入：850
更新关系：60
跳过重复：50
待处理冲突：20
失败：20
```

失败报告至少包含：

- 原始行号。
- 原始数据。
- 错误代码。
- 错误原因。

## 12. 数据导出

支持导出：

- 全集团资产，限集团授权用户。
- 某一家或多家子公司的资产。
- 某个业务系统的资产。
- 当前查询和筛选结果。
- 用户选中的资产。
- 某次填报任务的结果。

支持格式：

- CSV。
- XLSX。

大型导出采用后台任务。所有导出行为必须写入审计日志，并可配置导出文件的有效期。

### 12.1 当前轻量实现

当前版本已提供业务系统、网络资产台账和填报任务结果的 CSV/XLSX 即时导出：

- 集团管理员导出其全集团可见范围，子公司用户只能导出本组织授权范围。
- 网络资产支持按所属组织、资产类型、状态和关键字导出当前筛选结果。
- 填报任务结果按目标组织逐行导出，包含任务状态、组织填报状态、业务系统和网络资产数量快照、提交说明及审核结果；集团管理员导出全部目标组织，子公司只能导出本组织可见结果。
- CSV 使用 UTF-8 BOM，便于 Excel 正确识别中文；网络资产和业务系统按数据库每页最多 100 条查询，自定义字段值也按页加载并直接写入 HTTP 响应，不再构造全量 `[][]string` 或完整文件缓冲。填报任务结果同样逐行写出，避免额外的 CSV 文件缓冲。
- CSV 每个数据页主动刷新响应，导出接口单独使用 10 分钟有限写入截止时间，不再受普通 API 的 30 秒 `WriteTimeout` 截断；若客户端中断或响应写入失败，服务端只记录错误，不在半截 CSV 后追加 JSON。
- XLSX 提供中文表头、表头样式、冻结首行、自动筛选和适配列宽；由于 Excel 工作簿仍需在内存中构建，同步导出限制为最多 5,000 行，超出时提示改用 CSV。
- 响应头返回导出开始时授权与筛选范围内的总条数；CSV 仅在服务端完成全部响应写入后记录生成审计，并标记 `response_written_unconfirmed`，表示服务端已写出但无法确认浏览器最终保存成功。
- 选中资产导出、超过阈值的后台 XLSX 导出、下载文件有效期与过期清理仍作为后续增强。

## 17. 插件架构

### 17.1 插件定位

以下功能不进入核心系统，后续通过插件实现：

- 子域名发现。
- DNS 信息采集。
- HTTP/HTTPS 基础检测。
- SSL 证书检查。
- 端口检测。
- 消息通知。
- 云平台或第三方系统同步。

### 17.2 插件设计原则

1. 核心系统不依赖任何具体插件。
2. 插件通过核心服务接口操作正式资产，不直接随意修改核心表。
3. 插件维护自己的任务和原始结果表。
4. 插件发现结果先进入待确认资产，不直接进入正式台账。
5. 插件任务和结果必须带组织归属。
6. 子公司插件操作不能越过自身组织权限。
7. 第一阶段只支持官方内置模块化插件，不支持上传任意 ZIP 执行代码。

### 17.3 自动发现插件流程

```text
配置根域名和归属公司
  ↓
手动或定时执行发现任务
  ↓
发现子域名、DNS和基础HTTP信息
  ↓
执行集团范围重复检查
  ↓
写入对应公司的待确认资产
  ↓
子公司确认业务系统和负责人
  ↓
存在冲突时提交集团处理
  ↓
确认后录入正式资产台账
```

### 17.4 发现目标字段

- 根域名。
- 归属公司。
- 默认关联业务系统。
- 默认负责人。
- 授权说明。
- 执行周期。
- 超时时间。
- 最大并发数。
- 是否执行 DNS 解析。
- 是否执行 HTTP/HTTPS 检测。
- 是否启用。

### 18.7 安全测试、漏洞发现与整改工单

#### 18.7.1 当前 MVP 落地说明（2026-07-22）

第一期已落地以下数据库表：

```text

```

其中 `notification_reads` 只保存用户对动态消息的已读回执，不复制工单或风险接受的业务正文。

第一期已实现的实际状态链为：

```text
draft → issued → in_progress → pending_verification
                                  ├─ returned → in_progress / pending_verification
                                  └─ closed

非关闭状态可由集团取消为 cancelled
```

实现约束：

- 安全发现必须归属一个责任组织，并至少关联网络资产或业务系统之一；URL 与 IP 可以分别作为多项网络资产关联到同一业务系统，再分别登记发现。
- 一张安全工单只面向一个责任组织，可关联该组织的一项或多项安全发现；严重等级自动取关联发现中的最高等级。
- 集团管理员负责登记发现、创建、下发、复测退回、复测关闭和取消；子公司账号只能处理授权组织的工单。
- 每次状态变化同时写入不可覆盖的工单事件时间线和统一审计日志。
- 逾期根据 `due_at` 与当前时间动态计算，不额外写入逾期状态，避免状态不一致。
- 第一阶段不在核心系统执行扫描或攻击利用，也不保存明文口令；扫描器接入和漏洞批量导入后续扩展。
- 子公司可上传整改证明，集团可上传整改、复测或参考材料；单文件限制 20MB，仅允许 PDF、图片、TXT、CSV、XLSX、DOCX 和 ZIP。
- 附件存储使用随机服务端文件名，原始文件名只作展示；上传、下载权限继承工单组织隔离，上传和删除进入事件时间线与统一审计日志。
- 工作台提供未关闭、待集团复测、3 日内到期和已逾期工单数量；消息中心已补充站内消息、未读角标、已读回执和详情跳转，外部通知仍作为后续插件。

## 19. 技术落地方案

### 19.1 技术选型结论

系统第一版采用以下技术路线：

> Vue 3 + TypeScript 前端，Go 模块化单体后端，PostgreSQL 数据库，Podman Compose 私有化部署。

系统不采用微服务，不强依赖 Redis、消息队列、Elasticsearch 或 Kubernetes，优先保证集团内部部署简单、资源占用可控、后续维护方便。

### 19.2 总体技术架构

```text
浏览器
  │
  ▼
Vue 3 管理端
  │ REST/JSON API
  ▼
Go + Gin 后端
  ├─ 登录认证
  ├─ 组织权限
  ├─ 业务系统
  ├─ 网络资产
  ├─ 填报审核
  ├─ 安全测试批次
  ├─ 漏洞与安全发现
  ├─ 安全整改工单
  ├─ 站内消息中心
  ├─ 导入导出
  ├─ 数据安全属性
  ├─ 审计日志
  ├─ 后台任务
  └─ 插件运行框架
  │
  ▼
PostgreSQL
  │
  ├─ 本地文件存储
  └─ S3兼容对象存储（可选）
```

第一版采用模块化单体架构：各业务模块在代码和数据库层保持明确边界，但统一构建、统一部署和统一运维。未来只有在任务量或部署规模确有需要时，才拆分独立 Worker 或其他服务。

### 19.3 前端技术栈

```text
Vue 3
TypeScript
Vite
Element Plus
Vue Router
Pinia
Axios
```

各组件职责：

| 技术 | 用途 |
|---|---|
| Vue 3 | 前端视图和组件框架 |
| TypeScript | 类型约束和前端可维护性 |
| Vite | 开发服务器和生产构建 |
| Element Plus | 表格、表单、组织树、对话框、文件上传等后台组件 |
| Vue Router | 页面路由和路由权限控制 |
| Pinia | 登录用户、当前组织、权限和公共配置等全局状态 |
| Axios | REST API 请求封装 |

Pinia 只保存真正的全局状态，例如：

- 当前登录用户。
- 当前组织视角。
- 当前用户权限。
- 公共字典和系统配置。

业务系统、资产和填报任务列表等服务端数据按页面请求，不将全部业务数据长期保存在全局状态中。所有普通集合接口统一返回 `{ items, total, page, page_size }`，默认每页 20 条、单页最多 100 条并提供真实总数；即使请求页码超过最后一页，空页响应仍返回相同筛选和组织权限范围内的真实 `total`，便于前端安全回退上一页。详情中的高增长关联集合也必须拆分：业务系统详情仅返回系统信息和关联资产总数，关联网络资产通过独立分页接口加载；填报任务主列表仅返回任务及汇总计数，目标组织进度在展开任务时按需分页加载。CSV/XLSX 导出属于明确的全量处理场景，可在权限边界内使用专用查询生成完整文件，不复用普通列表接口规避分页。

### 19.4 后端技术栈

```text
Go
Gin
pgx
sqlc
REST API
OpenAPI
```

各组件职责：

| 技术 | 用途 |
|---|---|
| Go | 后端业务、后台任务和插件运行框架 |
| Gin | HTTP 路由、中间件、参数绑定、校验和文件上传 |
| pgx | PostgreSQL 驱动和连接池 |
| sqlc | 根据显式 SQL 生成类型安全的 Go 数据访问代码 |
| REST API | 前后端通信和后续外部集成 |
| OpenAPI | 接口定义、文档和客户端类型生成 |

核心资产、组织权限、填报审核等查询优先采用显式 SQL，不依赖复杂 ORM 自动关联。这样可以清晰控制：

- 组织及下级组织查询。
- 多组织用户授权。
- 集团范围重复资产检查。
- 资产多组织归属关系。
- 业务系统与资产多对多关系。
- 填报任务审核状态。
- 数据安全属性组合筛选。
- SQL 索引和执行计划。

### 19.5 数据库技术方案

数据库使用 PostgreSQL。

主要使用的数据能力包括：

- UUID：业务实体主键。
- `inet`：单个 IPv4/IPv6 地址。
- `cidr`：IP 网段。
- `jsonb`：少量扩展数据和插件配置。
- 标准时间类型：创建、更新、审核和快照时间。
- 事务：资产导入、审核、合并和归属调整。
- 索引：组织、系统编码、标准化资产值和常用筛选字段。

字段设计原则：

- 经常查询、筛选、统计和规则判断的字段使用普通数据库列。
- 不常查询且不同类型差异明显的扩展信息可以使用 `jsonb`。
- 不把核心业务字段全部放入 JSON，避免后续统计和索引困难。
- 数据库变更全部使用版本化迁移脚本管理。

数据库迁移工具采用 Goose 或同类 Go 迁移工具，迁移文件随代码版本提交并在部署过程中按顺序执行。

### 19.9 CSV/XLSX 处理

```text

```

导入采用以下流程：

```text

  ↓

  ↓
创建导入任务
  ↓
后台解析
  ↓
写入临时数据或导入批次
```

### 19.10 文件存储

后端定义统一文件存储接口，业务代码不直接依赖本地路径或某个云厂商 SDK。

```go
type Storage interface {

    Open(ctx context.Context, key string) (io.ReadCloser, error)
```

第一版提供两种实现：

1. 本地持久化目录，适用于简单单机部署。
2. S3 兼容对象存储，适用于集团已有 MinIO、私有云或其他对象存储环境。

建议目录分类：

```text
/data/uploads
/data/exports
/data/backups
```

导入、导出和备份文件应设置权限、保留期限和定期清理策略。

## 20. 非功能要求

### 20.1 性能目标

- 支持至少 10 万条网络资产的日常管理。
- 普通列表查询目标响应时间不超过约 1 秒。
- 万级数据导入不得阻塞普通 Web 请求。
- 大型导入和导出必须采用后台任务。
- 组织、系统编码、资产标准化值和常用筛选字段建立索引。

### 20.2 安全要求

- 密码使用安全哈希算法保存。
- 登录失败次数限制。
- 所有后端接口执行身份和数据范围校验。
- 文件类型、大小和内容校验。
- 防止 CSV/XLSX 公式注入。
- 导入文件隔离存储。
- 敏感配置加密保存。
- 重要操作完整审计。
- 插件不能绕过核心服务层修改正式资产。
- 默认按集团内部私有网络部署，不直接暴露公网。

### 20.3 备份恢复

当前版本采用“Web 受控备份 + 宿主机受保护恢复”的轻量化方案，不在 Web 核心系统中引入定时任务调度器：

- `scripts/backup.sh` 通过 `podman compose` 创建 PostgreSQL 自定义格式备份和应用附件卷归档，仍可作为宿主机运维入口。
- 集团管理员可在 Web 端“备份管理”创建、查看、校验、下载和删除备份；每个备份目录包含数据库文件、附件压缩包和 SHA-256 校验清单，生成成功前会验证两类归档均可读取。
- Web 创建备份使用受控的 `pg_dump` 与 `/data` 附件归档；创建窗口通过应用写入保护短暂拒绝新的保存、导入、下发等写请求，确保数据库快照和附件归档一致。不会将 Podman Socket 暴露给应用容器。
- Web 页面不提供在线恢复。`scripts/restore.sh --verify-only` 可在不修改数据的情况下校验备份完整性；正式恢复必须由具备宿主机权限的运维人员显式设置 `NETASSETS_RESTORE_CONFIRM=YES`，默认先自动创建恢复前安全备份，再覆盖数据库和附件。
- `make backup`、`make restore-verify BACKUP=...` 和 `make restore BACKUP=...` 提供统一宿主机运维入口。
- 定时调度和远端对象存储仍按实际运维要求后置实现，不进入当前轻量核心。

### 20.4 可维护性

- 核心模块和插件模块明确分离。
- 数据库变更使用版本化迁移。
- 配置通过环境变量或配置文件管理。
- 所有后台任务可查看状态、进度和错误信息。
- 应用日志、任务日志和业务审计日志分开管理。

安全测试批次圈选体验已增强：公网资产逐项选择改为服务端搜索和分页，不再受首屏 100 条候选限制；集团安全运营人员可按组织、业务系统或网络区域批量解析未归档公网资产，合并时自动去重并在匹配结果或合并结果超过 200 项时阻止纳入。最终请求仍只提交资产编号，由原有批次服务执行权限、状态、公网属性和授权快照冻结校验。

网络资产时效治理已完成第一阶段：资产可维护可选 `expires_at`，并已贯通在线维护、列表详情、模板、预检、导入、导出、字段级变更历史和填报快照差异；集团管理员可配置“资产到期”规则，命中后复用现有质量整改、集团复核、自动关闭和站内消息闭环。除人工巡检外，核心服务现支持按 `DATA_QUALITY_AUTO_SCAN_TIME` 和 `DATA_QUALITY_AUTO_SCAN_TIMEZONE` 每日执行一次全集团巡检，可通过 `DATA_QUALITY_AUTO_SCAN_ENABLED` 关闭。多实例使用 PostgreSQL 事务级 advisory lock 互斥，并以“自动巡检日期”唯一索引保证幂等；批次和审计以系统身份记录，不冒用管理员账号。失败保留服务端日志与失败审计，并按 15 分钟退避重试；单次执行最长 2 小时。人工与自动巡检均接入备份写闸门：备份窗口内人工巡检会被拒绝，自动巡检会延后重试；巡检执行期间也不会与备份快照并发。

导出资源控制已完成第三阶段：网络资产和业务系统 CSV 采用数据库分页查询、分页加载自定义字段值并直接流式写入 HTTP 响应，填报任务 CSV 采用逐行写出，不再持有完整 CSV 文件缓冲；每页写出后主动刷新。三类同步导出接口使用独立的 10 分钟有限写入截止时间，避免与普通 API 的 30 秒 `WriteTimeout` 冲突；流开始后的错误只记服务端日志，不会污染半截 CSV。CSV 完整写出后审计标记 `response_written_unconfirmed`，只说明服务端响应已写完，仍不把浏览器保存误记为已确认交付。

网络资产、业务系统和填报任务现均支持后台 XLSX 导出任务。同步 XLSX 仍统一限制为最多 `5,000` 行，前端识别超限响应后自动创建后台任务；用户也可主动选择“后台生成 XLSX”。后台 Worker 每次最多读取 100 条数据库记录，分页加载自定义字段值，并通过 Excelize `StreamWriter` 直接写入受控磁盘临时文件，完成后原子发布，不在内存中构建全量行或完整工作簿缓冲。任务创建时冻结资源筛选、当前工作组织、组织任职、角色和权限快照；网络资产与业务系统均沿用创建时的当前筛选条件，填报结果绑定具体任务。每个用户最多同时保有 3 个排队或运行任务，任务只允许申请人查询、下载和删除，其他用户即使是管理员也不能通过任务接口取得文件；这里冻结的是授权边界与筛选语义，实际导出行以 Worker 执行查询时的台账为准。完成后申请人仍可下载自己的结果，后续台账变化不会改写已经生成的文件。

后台导出成功或失败会产生仅申请人可见的 `export_job` 站内消息；成功文件默认保留 7 天，到期后任务标记为 `expired`、磁盘目录自动删除，下载返回 `410 Gone`。服务重启时，单实例部署会将遗留 `running` 任务恢复为 `queued` 后继续处理。创建任务与创建审计日志位于同一数据库事务，完成、下载和删除也分别留痕；用户界面只展示收敛后的失败提示，完整内部错误保留在服务端日志。

后续演进计划：为网络资产增加责任人账号绑定 `owner_user_id`，将到期问题精确通知到具体责任人；通过 API 或后续插件更新 `last_seen_at`；按需接入域名注册信息和 SSL/TLS 证书到期同步；当同一资产需要保存多个观测源、证书或域名技术事实时，再引入独立资产观测记录模型。每日自动质量巡检调度器及其多实例互斥、日期幂等和系统审计身份已经完成；自动发现和扫描插件仍按既定优先级后置。

下一步按需完善定时远端备份，以及阶段二至阶段四的高级能力（复杂多方归属冲突、可视化列映射、复杂多级会签）和外部通知（邮件、企业微信、钉钉、Webhook 的插件化通道）。独立集团安全运营角色及安全测试、漏洞、工单权限边界已完成；自动扫描和自动发现继续保持插件化后置，不增加核心系统重量。

## 23. 分阶段验收标准

### 23.1 V1.0 资产填报核心版

1. 集团管理员可以创建组织树、子公司和用户。
2. 用户只能访问自身角色和组织数据范围内的数据。
3. 子公司可以登记业务系统并维护负责人、状态和等级。
4. 子公司可以在线新增、编辑和软删除网络资产。
5. 网络资产可以关联一个或多个业务系统。
6. 同一资产被多家公司录入时，系统能够识别重复并进入关联或冲突处理流程。
7. 子公司可以通过 CSV/XLSX 导入业务系统和网络资产。
8. 错误数据不会导致整个导入任务失败。
9. 用户可以下载失败数据和具体原因。
10. 集团可以创建填报任务并选择参与子公司，也可以按全部、公网或内网网络资产限定专项核查范围，并在下发前预览各组织当前纳入范围的资源数量。
11. 子公司可以提交填报结果并接收集团退回意见，提交质量检查、数量与快照必须遵循任务核查范围。
12. 子公司从任务上下文新增的网络资产在提交前不得进入正式台账；需审核任务只有集团审核通过后才发布，无需审核任务在提交成功后自动发布。
13. 集团审核员可以通过或退回子公司提交的数据。
14. 集团可以查看各子公司的填报进度和数据质量情况。
15. 集团和子公司可以在授权范围内搜索、筛选和导出资产。
16. 业务系统和资产修改均有变更记录。
17. 登录、导入、导出、审核和删除等重要操作均有审计日志。
18. 删除的数据可以从回收站恢复。
19. 系统可以通过 Podman Compose 完成私有化部署。
20. 系统数据可以备份并成功恢复。
21. 未安装任何插件时，核心系统仍然完整可用。

### 23.2 V1.2 安全工单闭环版

1. 集团可以从审核后的互联网资产中创建测试范围并保存授权快照。
2. 集团可以在线登记或通过 CSV/XLSX 导入漏洞与安全发现。
3. 每条发现能够关联责任组织、具体资产和业务系统。
4. 集团可以将一条或多条同组织发现下发为安全整改工单。
5. 子公司只能查看和处理下发给本组织的工单。
6. 子公司可以接收、更新进度、填写整改结果并上传证明材料。
7. 集团可以登记复测结果，对工单执行通过关闭或退回整改。
8. 系统可以按严重等级配置默认期限并计算即将到期和逾期状态。
9. 风险接受必须由集团授权并记录原因、有效期和复审时间。
10. 漏洞证据、附件下载、期限调整、风险接受和工单关闭均有审计记录。
11. 集团和子公司工作台能够显示授权范围内的工单待办和整改统计。
12. 不启用扫描插件时，人工录入、批量导入和完整整改闭环仍能独立运行。

## 24. 已确定的产品决策

| 决策项 | 当前结论 |
|---|---|
| 产品定位 | 集团级轻量网络资产管理、填报与安全整改协同平台 |
| 使用主体 | 集团及下属多级子公司 |
| 核心层级 | 组织机构 → 业务系统 → 网络资产 → 安全发现与整改工单 |
| 部署形态 | 集团内部私有化部署 |
| 多租户 SaaS | 第一版不做 |
| 组织能力 | 支持集团、子公司和部门树 |
| 数据权限 | 全集团、本组织及下级、本组织、本人负责 |
| 业务系统 | 一等核心对象 |
| 数据安全属性 | 归属于业务系统，支持个人信息、敏感个人信息、数据量、分类分级等字段 |
| 数据量阈值 | 保存原始数值、统计口径和基准日期，是否超过10万条等由规则自动计算 |
| 自定义字段 | 由集团统一定义和维护，子公司按权限填写 |
| 网络资产模型 | 集团统一资产实体 + 多组织关系 + 多系统关联 |
| 日常修改 | 直接生效并记录变更 |
| 集中盘点 | 任务中新建网络资产先进入草稿；需审核任务通过后发布，无需审核任务提交后自动发布 |
| 安全治理闭环 | 审核后的互联网资产 → 授权测试范围 → 漏洞发现 → 安全工单 → 子公司整改 → 集团复测关闭 |
| 工单边界 | 只做安全整改工单，不建设通用 ITSM 和复杂 BPM |
| 工单组织隔离 | 一张工单只面向一个责任组织；同一问题涉及多家公司时分别生成子工单 |
| 漏洞来源 | 第一版支持在线登记和 CSV/XLSX 导入，自动扫描结果后续通过插件或 API 接入 |
| 删除方式 | 默认软删除 |
| 导入格式 | CSV、XLSX |
| 自动发现 | 不进入核心，后续通过插件加入 |
| 插件结果 | 先进入待确认资产，不直接进入正式台账 |
| 插件方式 | 官方内置模块化插件优先 |
| 第三方插件上传 | 第一版不支持 |
| 后端架构 | 模块化单体 |
| 前端建议 | Vue 3 + TypeScript + Element Plus |
| 后端建议 | Go + REST API |
| 数据库 | PostgreSQL |
| 大型任务 | PostgreSQL任务表 + 应用内Worker |
| 部署方式 | Podman Compose 优先 |

## 26. 总结

本系统的准确定位为：

> 一个面向集团和多级子公司的轻量网络资产管理、填报与安全整改协同平台。集团负责标准、任务、审核、安全测试发现和整改监督，子公司负责业务系统登记、网络资产维护及安全工单整改；自动发现和自动扫描通过插件扩展。

核心业务关系：

```text
组织机构
  ↓
业务系统
  ↓
网络资产
```

核心管理闭环：

```text
集团下发资产填报任务
  ↓
子公司填报并提交
  ↓
集团审核形成统一台账
  ↓
集团基于互联网资产开展授权安全测试
  ↓
登记漏洞并下发安全整改工单
  ↓
子公司整改并提交验证
  ↓
集团复测通过后关闭
```

核心架构原则：

```text
统一资产实体
+ 多组织归属
+ 多业务系统关联
+ 后端数据范围权限
+ 填报审核闭环
+ 安全工单整改闭环
+ 完整变更留痕
+ 插件化扩展
```
